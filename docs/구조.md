# 공시캘린더 구조

공시와 시세를 **들여오기 → 계산 → 보여주기** 세 층으로 처리한다. 원천은 한 번만 받고 한 번만 읽으며, 계산은 바뀐 것만 한 번 돌린다.

```
[1 들여오기]  ingest — 앱에서 네트워크를 쓰는 곳은 여기만
   공시 목록 ─(새 접수번호만)→ 종류별 등록표 ─→ 그 종류 파서 한 번 → 사실 저장소
   외부 원천(컨센·배당 이력·현금흐름·시세) ─(정해진 주기)→ 같은 저장소
        ▼
[2 계산]  derive — 저장소만 읽고 결과 파일만 씀, 네트워크 금지
   계산마다 "읽는 종류"를 적어 두고, 그 종류에 새 사실이 들어왔거나 날이 바뀐 계산만 의존 순서대로 돌림
        ▼
[3 보여주기]  web — 결과 파일만 읽음
```

## 폴더

```
core/        공용 기반 — 경로·원자 저장·영업일·만기 규칙 (네트워크 없음, 어느 층이든 import)
ingest/
  run.py       한 바퀴: 새 공시·주기 원천 → 파서 → 저장소, 바뀐 종류 목록을 돌려줌
  registry.py  공시 종류 → 파서 / 외부 원천 → 주기
  store.py     사실 저장소 읽기·쓰기, 파서 버전, 영구 실패 기록
  sources/     접속만 (값 해석 없음) — net · dart · kind · naver · kis · mirror
  parsers/     원문 → 값 (순수 함수, 접속 없음)
derive/
  registry.py  계산 → 읽는 종류·앞 계산
  run.py       바뀐 종류를 받아 해당 계산만 의존 순서대로
  dividend/ …  영역별 계산
app/         monitor(루프: ingest.run → derive.run → 알림) · serve · launch
web/         index.html · dividend/ · common/
data/
  store/       사실 저장소 (종류별 파일, 접수번호마다 한 줄)
  out/         계산 결과 (화면·엑셀·CI 배포가 읽음)
  cache/       토큰·고유번호·시세 DB·공시 목록 원본
```

## 규칙 (코드로 검사)

- 공시 종류 하나에 파서는 하나다. 다른 영역은 파서를 새로 만들지 않고 그 파서가 쌓은 사실을 읽는다.
- 등록표 검사 — 종류 하나에 파서 둘, 아무도 안 읽는 종류, 계산이 읽는데 파서가 없는 종류가 있으면 시작할 때 오류.
- 층 검사 — `derive`·`web`은 `ingest`를 import 할 수 없다. CI에서 실패.
- 파서 모양은 `원문 → 값` 하나, 계산 모양은 `저장소 → 결과` 하나.
- 받은 것은 다시 받지 않는다. 파서 버전을 올린 종류만 저장된 공시를 다시 읽는다. 영구 실패(본문 없음 등)는 이유와 함께 남겨 다시 시도하지 않는다.
- 계산은 순수하다 — 같은 저장소·같은 날이면 같은 결과. 전 종목 재계산이 싸므로 종목 단위로 쪼개지 않는다.

## 확장 규칙 — 새 이벤트·새 공시가 생길 때

| 생기는 일 | 새로 쓰는 것 | 고치는 기존 코드 |
|---|---|---|
| 새 공시 종류를 읽음 | `ingest/parsers/` 파서 하나 + 등록표 한 줄 | 없음 (지난 공시까지 들여오기가 채움) |
| 새 외부 원천 | `ingest/sources/` 접속 하나 + 등록표 한 줄(주기) | 없음 |
| 새 이벤트 계산 | `derive/` 계산 하나 + 등록표 한 줄(읽는 종류) | 없음 |
| 기존 계산에 새 자료 | 신호 함수 하나 | 그 계산의 신호 목록 한 줄 |
| 이미 읽는 공시에서 칸을 더 뽑음 | — | 그 파서 + 버전 올림 (저장된 공시만 다시 읽음) |
| 화면에 새 탭·칸 | 화면 코드 | 화면만 |

`ingest/run.py`·`ingest/store.py`·`derive/run.py`·`app/monitor.py`는 새 이벤트 때문에 바뀌지 않는다. 바꿔야 한다면 구조를 먼저 고친다.
